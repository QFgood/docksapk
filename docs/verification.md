# v0.1.0 验收记录

## 已验证

| 环节 | 结果 |
| --- | --- |
| Go API | HTTPS 测试通过，覆盖一次性码并发兑换、设备撤销、两设备同步编辑、版本冲突、幂等新增、服务重启后数据保留 |
| 导入 | 同一清单重复导入不产生重复卡片，覆盖字段保留，取消覆盖恢复来源值，完整清单中的缺项被隐藏 |

| Ubuntu 采集 | Linux amd64 采样真实主机指标和 Docker 容器，记录退出码 7 与健康检查失败，状态 API 返回不健康快照 |
| Android 构建 | Gradle Wrapper 在 JDK 17 上完成 Debug、Release 和 Lint。Lint 无错误 |
| APK 签名 | v2/v3 签名及 APK 对齐通过，最低 API 26、目标 API 35，包含 arm64-v8a、armeabi-v7a、x86、x86_64 |
| API 文档 | OpenAPI 3.0.3 YAML 可解析，内部引用可解析 |

测试命令和部署方法见[部署与升级](setup.md)。

## v0.1.3 后端升级补验

使用发布页的 Linux amd64 后端在独立环境完成以下操作。测试连接使用 HTTPS 和隔离的 SQLite 数据库。

- 在 v0.1.0 运行期间创建 SQLite 一致快照，完整性和外键检查通过。
- 原库升级到 v0.1.3 后，旧配对、卡片覆盖、事件、已读状态和前后两次设备撤销均保留。
- 将快照恢复到新数据库路径后，可以继续访问并编辑卡片。恢复以快照时间点为准，测试中重新应用了快照之后的撤销。
- 使用同一快照和 v0.1.0 二进制回滚后，已有配对和历史仍可查询。
